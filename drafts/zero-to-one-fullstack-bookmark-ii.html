从无到有做全栈，实现一个书签应用（二）

Posted on Fri 09 May 2025 in Computer Science

  1. Missing Input Validation: The URL field is not validated for proper URL format; No length limits on title, description, or tags; No sanitization of user input before storing in the database
  2. CORS Configuration: The CORS middleware is enabled without any specific configuration (app.use(cors())); This allows requests from any origin, which could be a security risk
  3. Error Handling: Detailed error messages are being sent to the client; Stack traces might be exposed in production; Missing Rate Limiting: No rate limiting on API endpoints
  4. Could be vulnerable to DoS attacks: Missing Authentication/Authorization, No authentication system in place Anyone can create, read, update, and delete bookmarks; No user-specific data isolation

  5. Missing Security Headers: No security headers like Helmet.js are implemented Missing headers like X-Content-Type-Options, X-Frame-Options, etc.

  6. Hardcoded API Endpoints: The application has hardcoded API endpoints to http://localhost:3000

  7. Error Handling Improvements, The error handling is basic and might not cover all edge cases:
  8. Missing Loading States: Some operations like delete and edit don't show loading states to users. Solution: Add loading indicators for all async operations to improve user experience.
  9. Missing Backend Validation The client performs minimal validation:
  10. Missing Authentication/Authorization: There's no visible authentication or user management in the current code: Solution: If this is a multi-user application, implement authentication and ensure bookmarks are associated with specific users.
  11. Responsive Design Issues: The CSS uses fixed widths in some places:
  12. Missing Types Definition: I don't see the complete IBookmark interface definition: Solution: Ensure all TypeScript interfaces are properly defined and used consistently.
  13. Missing Pagination: The application fetches all bookmarks at once:

我应该使用哪个东西部署？

Since this is a hobby project, we should get to things that are as cheap as we can get.

Express.js Web Backend服务 * Google App Engine: seems includes free tier, instance type F1 and 850 hour / mo free, further investigation; https://cloud.google.com/appengine/docs/standard/nodejs/building-app * Railway: 30天免费$5 credit，之后hobby tier $5 * Render: Hobby tier 免费；Free backend instances sleep after 15 minutes of inactivity, causing cold starts * Fly.io: pay by usage, 比如shared-cpu-1x, $0.0027/hour, $1.94/mo

Google App Engine

https://cloud.google.com/appengine/docs/standard/nodejs/building-app/creating-project Create GCloud Project or Use an existing one Enable Cloud Build API: 点点鼠标就行 安装gcloud cli： https://cloud.google.com/sdk/docs/install create app engine application: nothing particular, just choose a location -- I chose us-west2 just because it is geogrpahically closer
